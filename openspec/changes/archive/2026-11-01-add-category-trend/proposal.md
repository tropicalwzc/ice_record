# Proposal

## Why

走势页目前只有一条总资产曲线，用户看不出涨跌是哪一类资产推动的：股票赚了、基金亏了，在总额上互相抵消，曲线只剩一条平线。同时横轴日期写作「9月22日」，标签偏宽挤占绘图区，首尾日期还要为半个标签宽让出白边，曲线本身能铺开的面积被进一步压缩。

要把「变没变」变成「谁在动」，必须先把每日快照从「只有一个总额」扩展成「总额 + 分类小计」。

## What Changes

- **每日快照连带记录分类小计**：新增 `snapshot_category` 表（v3 迁移），每次写当日快照时同步写入 7 个类别各自的金额（为 0 也写），与总额在同一事务内完成，存量语义不变。
- **走势页新增视图切换**：`总资产 / 复合 / 各分类` 三档，放在标题栏右上角的菜单里。
- **横轴不再显示日期文字**：只保留等距竖向网格线，两端留白从「一个整标签宽」收回到 1.5% 时间余量；区间起止日期改由图表下方一行文字给出，具体某一天仍靠长按气泡读取。复合柱状图例外，每期日期照常显示。
- **放大绘图区**：图表行去掉卡片内边距、纵轴标签缩短为整数、图表高度由 240 提升到 300，绘图区面积约 +45%。
- **复合模式改为分组柱状图**：横轴是时间桶，每桶内按类别分组，**柱高是该类别相对上一桶的变化量**（零轴上下的方向即涨跌），柱色用类别色标识身份。桶数按绘图区宽度反算自动收缩，不硬塞。
- **图表下方新增「本周期各模块变化幅度」列表**：按变化绝对值降序，给出期末金额、变化额、变化率、涨红跌绿，末行合计；其累计值恒等于柱状图所有柱之和。
- **单个类别模式仍用折线**：只画该类别的曲线，纵轴按该类别自身的取值范围算，区间统计与选中气泡跟随当前类别。
- **曲线支持左右滑动翻看历史**：载入上限从「最近 30 天」放宽到日 730 / 周 260 / 月 120 / 年 50 个点；一屏最多 90 个点，超出即可左右拖动，默认停在最近一屏。纵轴范围、区间统计与长按读数都只按当前这一屏计算，图表下方同时给出「这一屏」和「全部」的日期范围。
- 历史记录列表保持每日总额不变，不因视图切换而变化。

## Capabilities

### New Capabilities

无。分来源走势是既有走势能力的扩展，不新开能力边界。

### Modified Capabilities

- `asset-tracking`: 「每次改动自动记录当日总资产」要求扩展为同时记录当日分类小计；新增「分类小计与总额同事务同覆盖」的约束。
- `asset-trend-chart`: 横轴日期格式要求改为数字族并提高刻度上限；新增「按类别切片」的曲线要求、「复合模式下用变化量分组柱状图」的展示要求，以及「本周期各模块变化幅度列表」的读数要求。

## Impact

- **数据库**：`AppDatabase` 新增 v3 迁移（`snapshot_category` 表）、读写方法，以及快照删除时的级联清理；`seedDemoHistoryIfNeeded` 需同步生成分类数据。
- **模型**：`AssetSnapshot` 增加分类小计；`TrendPoint` 需要能承载单个类别的取值；`TrendAggregator` 增加按类别归并的入口。
- **视图**：`TrendView` 改动最大（视图切换、柱状图、幅度列表、横轴格式、绘图区尺寸）；`StatsPeriod` / `TrendAxis` 的标签格式调整。
- **同步**：`SyncRecord.snapshot` 的字段集合增加分类小计，内嵌进按年分片的快照文件，不新增记录类型；`applyRemote` 需一并合并。
- **测试**：`TrendAggregatorTests` 增加按类别归并与首个桶无变化量的用例；`AppDatabase` 的迁移与覆盖写需覆盖测试；`AssetStoreTests` 增加写入分类小计的断言。
- **工程**：若新增源文件，需重新执行 `xcodegen generate`。
- **数据边界**：分类明细只能从本版本上线当天起积累，更早的历史日期没有分类数据，复合视图与分类视图的横轴范围因此短于总资产视图——这是可接受的已知限制，不做任何按比例倒推的补造。
