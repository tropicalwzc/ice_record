# Verification

本文件记录 `add-category-trend` 的验证边界：哪些已经被自动化覆盖，哪些只能在特定环境下人工确认。

## 本机验证环境

| 项 | 值 |
|---|---|
| Xcode | 27.1 (27A9275) |
| 模拟器 | iPhone 16 Pro Max / iOS 18.3.1 |
| 目标 | `platform=iOS Simulator,id=E7929D1F-E52D-4CC8-8F72-6C74EF607155` |

两处与 `openspec/config.yaml` 的差异，属环境限制而非改动：

1. 配置里写的 destination 是 `iPhone 16 Pro / OS=18.4`，本机没有这个组合（只有 18.3.1），改用设备 id 指定。
2. 本机的构建沙箱不允许 `sandbox-exec` 再嵌套，Swift 宏插件（`@Observable` / `@State`）会直接展开失败，
   报 `swift-plugin-server produced malformed response`。验证时在命令行临时追加
   `OTHER_SWIFT_FLAGS='$(inherited) -Xfrontend -disable-sandbox'` 绕过，**没有写进 `project.yml`**。
   这个参数只解决本机验证，不该出现在工程配置里。

## 已被自动化覆盖

- v3 迁移：新建库直接是 v3；从手工构造的 v2 库升级后分类表可用、老快照不丢（`SnapshotCategoryTests`）。
- 分类行读写：一天固定 7 行（含 0）、覆盖而非累加、分类合计等于总额、墓碑级联删除。
- 批量读取不退化成 N+1（用 `snapshotCategoryStatementCount` 断言只发一条语句）。
- `AssetSnapshot.categories` 的 `nil`（无明细）与「全 0」可区分。
- 同步：旧记录的编解码兼容、远端带分类的合并、更新记录无分类时清掉本地旧明细、
  分类合计与总额不自洽的记录被跳过且不阻断整轮同步。
- 分类归并：桶内取最后一次记录、首桶 `delta == nil`、`delta == 0` 与 `nil` 区分、无明细的日子不补 0 值点。

## 无法自动验证，需要人工确认

1. **真机 iCloud 往返**。传输层被 `SyncTransport` / `CloudFileStore` 抽象，合并语义已用 mock 覆盖，
   但两台真机之间的实际推送 / 拉取、分片文件的重写、iCloud 侧延迟回灌都无法在模拟器复现。
   人工步骤：两台设备登同一 Apple ID，各改一条资产 → 各同步一次 → 确认对方设备的当日分类小计与总额一致。
2. **新旧版本共存的字段兼容**。旧版本 App 读到多出来的 `cat.*` 字段应当忽略，新版本读到旧记录应当按「无明细」处理；
   后者有单测，前者需要用一个旧 build 实测（模拟器无法并存两个 bundle id 相同的构建）。
3. **图表观感**：横轴刻度在 iPhone SE / iPad 上的实际排布、柱宽是否达到 5pt、气泡是否被裁切。
   这些依赖真实渲染，只能目视。
4. **分类明细起点的用户感知**：老库升级后分类视图只有当天一个点，空状态文案与 footer 是否说得够清楚，
   属于主观判断。

## 实施后的两轮返工（都来自实机观感）

1. **复合模式曾把用户困住**。视图切换菜单原本只挂在图表 Section 的 header 上，
   而空状态分支整块替换了那个 Section——数据不够时菜单跟着消失，切过去就出不来。
   修法：空状态的 `actions` 里也放同一个菜单（共用一份 `scopeMenu`），
   截图确认「还不够画出变化」页面上有「复合 ⌄」按钮可点。
2. **横轴日期标签被整个去掉**。最初按「半个标签宽」留白，iOS 27 SDK 上标签变成左对齐 → 右端被裁成 `11-0|`；
   改成整字宽留白 + `centered: true` 后，Charts 干脆不画贴边的最后一个标签（`11-01` 消失）。
   用户随后指出：既然不需要日期，就该把这块面积还给曲线。于是删除 `TrendAxis`（含 8 条测试）、
   横轴只留网格线、两端留白收到 1.5%，区间信息移到图表下方一行文字。
   **这条推翻并替换了原规格里的「横轴日期刻度必须可读」整条需求**（走 REMOVED + ADDED，不是 MODIFIED）。

## 滑条只能人工拖

`TrendView` 的区间切换依赖一条 `Slider`，而本机模拟器**没有图形界面、无法产生拖拽手势**。
可自动验证的部分被刻意抽到 `TrendWindow`（是否显示滑条、默认偏移、越界夹紧、按偏移切一屏）并写了 6 条单测；
下面这些只能人工在 Xcode 里跑一次：

1. 拖滑条时曲线是否跟着换段、松手是否停住（不回弹）。
2. 拖到两端时是否停在最早/最新一段，纵向不再变化。
3. 换段时纵轴重新定标会不会跳得难受（理论上只在跨刻度格时变化）。
4. 长按选点与拖滑条互不干扰：长按仍能出气泡。

## 圆角裁切需要目视复查

`insetGrouped` 的 section 是**圆角裁切**的，而图表的纵轴数字长在左侧那两处圆角里。
现在不再靠「躲」：图表挪到了 section 的 header 上（header 不受卡片裁切），
卡片自己画成**四角直角**（`Rectangle`），纵轴数字所在的两块区域根本没有圆角。
只削左角的那一版在视觉上偏斜，所以右侧也一并削平——与同页其他圆角卡片风格不统一是刻意的取舍。
另有两点只在特定条件下暴露，需留意：

1. header 的内边距比卡片多约 10pt，用负 padding 补的。**换 list 样式或 iPad 分栏时要重量**。
2. Charts 不会把自己裁进 frame，面积填充会溢出——以前被 List 的圆角裁切盖住，现在靠显式 `.clipped()`。
   如果哪天去掉这行，蓝色会重新压到滑条和页脚上。
3. 负 padding 只撑大内容、不撑大底色：`.background` 必须写在它**之前**。
   写反了就会出现「曲线越出卡片右侧」——底色按没撑开的尺寸画，内容却已经伸出去。
4. 外扩量 20pt 是从 440pt 宽的设备上量的（header 内容 40…400，卡片 20…420）。
   换到 iPad 分栏或别的 list 样式时，这个数要重新量，否则卡片会比其他卡片宽或窄。

## 几个必须说清楚的取舍

1. **纵轴整数的例外**。规格要求「纵轴刻度不带小数」，实测在总资产量级（十几万）上，整数刻度会退化成
   `19 / 20` 两根，等于没有刻度。因此实现上先取「好看的步长」，步长 ≥ 1 万时一律整数，
   只有变化量小到零点几万（复合柱状图的典型量级）时才保留一位小数。规格要防的是「187.5」这种没必要的精度，
   不是禁止一切小数。
2. **x 轴留白从不正确。** 原设计两端各留「半个标签宽 + 8pt」，是按「标签居中」算的。
   本机 Xcode 27.1 的 SDK 把标签渲染成贴着刻度左对齐，右端 `11-01` 被裁成 `11-0|`（有截图为证）。
   改成两端各留**一个完整标签宽**：对居中和左对齐两种行为都成立，代价是两端各多让十几个点。
   delta 已同步写进 spec 的场景「标签左对齐时右端日期不被裁掉（回归）」。
3. **桶数的两个天花板**。只按「每根柱 ≥ 5pt」算，类别从 6 个降到 4 个时桶数会从 8 涨到 11，
   桶下的日期直接连成「10-2310-24…」。所以桶数同时受「日期标签宽度」约束。
4. **截图是怎么拍的**。模拟器没有图形界面、无法点击，验证时临时把 `RootTabView` 的默认页签设成「走势」、
   把 `TrendView` 的默认 scope 依次设成 `.total` / `.composite` / `.category(.stock)`，各截一张图后**全部还原**，
   `git diff` 确认这两个文件没有留下任何临时改动。
5. **`xcodegen generate` 会踩的两个坑**（本次已处理）：
   - `project.yml` 的 iCloud 容器数组原本是空的，generate 会把 `IceRecord.entitlements` 里写死的
     `iCloud.com.icerecord.app` 覆盖成空数组，真机同步会落到默认容器上。已在 `project.yml` 补齐容器 id，
     再 generate 后 entitlements 无差异。
   - generate 会把 `IceRecord.xcscheme` 重置成默认配置（启动配置 Release → Debug、去掉「不挂调试器」等）。
     这些是手工调过的，已用 `git checkout` 还原；**以后再 generate 仍需手工还原 scheme**。
