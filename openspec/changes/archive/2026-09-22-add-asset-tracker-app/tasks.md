## 5. iCloud 同步：存储与传输层

- [x] 5.1 先用 CloudKit 实现一版，确认其需要自定义 zone 与服务端 schema、正式环境还要手动 Deploy，且失败只返回不带原因的 `CKError 15 serverRejectedRequest`；放弃该路线。
- [x] 5.2 改用 `NSUbiquitousKeyValueStore` 实现，确认其 1MB 是全部键共享的总配额、拆键无法规避；放弃该路线。
- [x] 5.3 确定采用 iCloud 云盘文件：条目一个文件，快照按自然年分片，一年一个文件。
- [x] 5.4 定义 `SyncRecord` / `SyncValue` 与紧凑编码（类型短码 + 数组带类型标记 + 手写 `Codable`），并用 raw DEFLATE 压缩。
- [x] 5.5 文件后缀定为 `.json.deflate` 而不是 `.json.gz`，因为 `NSData.compressed(using: .zlib)` 输出的是裸 deflate、没有 gzip 头。
- [x] 5.6 抽象 `CloudFileStore`：协议 + iCloud 云盘实现（用 `NSFileCoordinator` 协调读写）+ 本地目录实现（测试与 Debug 使用）。
- [x] 5.7 实现 `SyncFileLayout`：记录到文件名的映射、按年解析、以及无法定位时的处理。
- [x] 5.8 实现 `FileSyncTransport`：按目标文件分组、读远端、按 `updatedAt` 合并、写回；拉取时按文件指纹（大小 + 修改时间）跳过未变化的文件。
- [x] 5.9 让 `push` 写完立刻更新内存中的指纹索引，使紧接着的 `pull` 不会重读自己刚写的文件。
- [x] 5.10 云端文件无法解码时按空处理并跳过，不中断整轮同步；下一次推送用本机数据重建该文件。

## 6. iCloud 同步：引擎、生命周期与容错

- [x] 6.1 数据库迁移 v2：两张表加 `deleted_at`（墓碑）与 `sync_dirty`，新增 `sync_state` 表存放上次同步时间与文件指纹索引。
- [x] 6.2 把删除改成写墓碑（`deleted_at` + 新 `updated_at` + 标脏），所有查询过滤 `deleted_at IS NULL`。
- [x] 6.3 实现 `SyncEngine`：先推后拉；推送后只把真正写入的记录清脏，被拒绝的留在脏列表；拉取后逐条按 last-writer-wins 合并；整轮成功才推进指纹索引。
- [x] 6.4 iCloud 不可用时整轮跳过并抛 `accountUnavailable`，本地数据一个字都不改、脏标记保留。
- [x] 6.5 实现 `SyncCoordinator`：开关持久化、启动同步、回前台同步、本地改动后 3 秒去抖同步、手动同步、以及云端变化通知触发同步。
- [x] 6.6 所有跨进程等待加超时（账号查询 8 秒、整轮 40 秒），用 `ResumeOnce` 保证续体只被恢复一次，修复界面永久卡在「正在同步…」的问题。
- [x] 6.7 单条记录失败不再中断整轮同步：成功的照常清脏，失败的留待下次并单独提示原因。
- [x] 6.8 修复「重装 App 后条目重复」：样例数据的自动播种与云端回灌的数据标识不同、无法去重，改为完全取消启动播种。
