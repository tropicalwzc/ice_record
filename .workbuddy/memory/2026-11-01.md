## 变更提案 add-category-trend（走势图分资产来源）

探索后定稿并生成变更（4 个工件全 done，`openspec validate --strict` 通过，7 个 delta ≤ 上限 10）。

产品决策（用户在探索中逐条确认）：
- 分类历史**不做回填估算**：v3 新增 `snapshot_category(day, category, amount)`，从上线当天起积累；
  每天写全 7 类（含 0），与总额同事务、同覆盖、墓碑级联删除。
- 复合模式用**分组柱状图**，柱高 = 相对上一桶的**变化量**（不是金额，这样才能消除量级压平），
  柱色只标识类别身份（涨跌靠零轴上下位置），首桶无基准不画柱。
- 图下方新增「本周期各模块变化幅度」列表，累计值须等于所有柱之和。
- 横轴改数字族：日/周 `MM-dd`、月 `yyyy-MM`/`M月`、年 `yyyy`；刻度上限 5→6。
- 绘图区放大四招：行内边距清零、纵轴整数标签、高度 240→300、短日期；禁用 `chartPlotStyle(padding:)`。

技术决策（design.md 里的 D1–D10）：
- 分类明细内嵌进当天快照的同步记录，不新增记录类型；**不做字段级合并**（否则总额与分类会错配）。
- `delta` 必须是 `Double?`：`nil` = 无基准（不画柱），`0` = 真的没动（0 高柱 + 列表「持平」）。
- 柱状图桶数与类别数按绘图区宽度反算（每根柱 ≥5pt），不足时先减桶、再 Top5+其他。
- `plotWidth` 估算常量 64→52（纵轴改整数后标签变窄），保留「宁可少放一个刻度」的取舍。

### 本机环境必须记住的三件事

1. **沙箱里无法编译 Swift 宏**：`swift-plugin-server` 需要嵌套 `sandbox-exec`，被拒后报
   `produced malformed response`。解法：命令行追加
   `OTHER_SWIFT_FLAGS='$(inherited) -Xfrontend -disable-sandbox'`（**不要写进 project.yml**）。
2. **`xcodegen generate` 会改两个不该动的文件**：
   - `IceRecord/IceRecord.entitlements`：project.yml 的容器数组原来是空的，generate 会把
     `iCloud.com.icerecord.app` 抹成空数组。**已在 project.yml 补齐容器 id**，现在 generate 后无差异。
   - `IceRecord.xcodeproj/.../IceRecord.xcscheme`：会被重置成默认配置（Release→Debug、去掉不挂调试器）。
     **每次 generate 后都要 `git checkout` 还原**。
3. **模拟器没有图形界面、无法点击**：截图验证靠临时改 `RootTabView` 默认页签 + `TrendView` 默认 scope，
   截完必须还原（本次已还原，git diff 无残留）。

## 图表卡片左侧圆角（用户要求取消）

- 结论：**insetGrouped 的 section 会裁切 body 每一行**，`listRowBackground` 换 `UnevenRoundedRectangle`
  和「行内自绘背景 + rowBackground clear」都会被切回圆角（用红色背景实测确认）。
- 唯一可行的解法：把图表挂到 **section 的 header**（不受卡片裁切），自己画「左直角 + 右圆角」的底。
  代价：header 内边距比卡片多约 10pt，要用 `.padding(.horizontal, -10)` 补回对齐。
- 附带发现：**Charts 不会把自己裁进 frame**，面积图填充会溢出到框外；以前被 List 的裁切盖住了，
  挪到 header 后必须显式 `.clipped()`，否则蓝色压到滑条和页脚上。
- 规格改写为「图表卡片左侧不留圆角」；design 记 D12（含试错记录）。

## 修复：曲线越出卡片右侧

- 现象：图表内容（右端面积填充、左端纵轴数字）跑到卡片外的页面底色上。
- 根因：`.padding(.horizontal, -10)` 只把**内容**撑大，视图对外报的尺寸仍是没撑开的那份；
  `.background` 写在 padding **之后** → 底色按未撑开的宽度画，内容比底色宽。
- 修法：顺序改成 `内容 → .background(形状) → .clipShape(同一形状) → .padding(.horizontal, -20)`；
  外扩量按实测从 10 改成 20（header 内容 40…400，卡片 20…420，440pt 宽设备）。
- 顺带给图表加 `.padding(.leading, 4)`，纵轴数字不再贴着卡片左缘（原来只剩 3pt）。
- 验证手段：写了个 Swift 的像素扫描工具（`/tmp/edges.swift`）逐行打印非页面底色的左右边界，
  比肉眼看截图可靠。卡片现跨 20…420pt，与「区间统计」严格对齐。
- 测试 74 单元 + 3 UI 全绿。
